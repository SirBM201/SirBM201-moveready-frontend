# MoveReady V1 — Design Completion Standard

## Product promise
MoveReady is a Global Opportunity & Mobility Platform. A user starts with their real situation and goal; the platform helps them FIND a realistic opportunity, QUALIFY for it, MOVE through execution, SETTLE, GROW and FIND AGAIN.

## 1. One profile, many engines
The same profile must power opportunity/pathway recommendations, local/international jobs, language targets, financial readiness, document requirements and execution. Do not ask for the same fact repeatedly when it is already known.

Minimum unified profile domains: nationality/passport; current residence; residence/work authorization; education; work history; occupation; skills; languages; finances; family; relocation preferences; target countries; career goals.

## 2. One opportunity model
Every recommended opportunity should eventually expose five distinct dimensions rather than one misleading score:
- Opportunity Fit — how well the opportunity matches the user's goals/profile.
- Eligibility/Readiness — how close the user is to formal requirements.
- Career Match — for jobs, skills/experience relevance.
- Application Viability — legal/work-authorization/sponsorship realism.
- Financial Readiness — ability to meet known funds + execution budget.

A score must never imply guaranteed approval, employment, admission or entry.

## 3. Recommendation orchestration
For each saved/recommended opportunity MoveReady should answer:
1. Why this is relevant.
2. What is already satisfied.
3. What is missing.
4. Which blocker matters most.
5. What the user should do next.
6. Which MoveReady workspace performs that action.
7. Which official source/rule date supports the recommendation.

## 4. FIND
Entry points: Opportunity/Route Finder; Local/International/Both Jobs; Passport/Visa Power; country/pathway comparison. Users must not need to know a programme name first.

## 5. QUALIFY
Entry points: job matching/application realism; CV/cover letter; readiness gaps/action plan; Language Coach with English/French/Both; IELTS General; TEF Canada; Practice Bank; Mistakes Bank; adaptive microlearning.

## 6. MOVE
Entry points: requirements; document checklist/status/expiry; deadlines/rule monitoring; financial readiness/proof-of-funds; application/job tracking. A selected opportunity should generate an execution checklist rather than leaving the user to reconstruct requirements manually.

## 7. SETTLE → GROW → FIND AGAIN
Preserve settlement and post-relocation value. After arrival, local job search, better-job discovery, career progression, renewals, certifications and family settlement become primary. Successful relocation is a lifecycle transition, not product churn.

## 8. Trust design
- Prefer fewer realistic opportunities to many unusable results.
- Distinguish official facts, MoveReady analysis and user-entered data.
- Show provenance and rule/update dates where rules drive decisions.
- Never hide a known sponsorship/work-authorization blocker behind a high skills score.
- Do not invent official financial thresholds.
- Language content must be original or legally usable official material.
- Keep advisory language clear without making the product timid or unusable.

## 9. UX completion criteria
- Goal-first onboarding.
- Clear FIND/QUALIFY/MOVE navigation.
- Mobile-first cards and forms.
- Useful empty/loading/error states.
- No dead-end results: every result has a next action.
- No duplicate data entry where unified profile data exists.
- Local job users are not burdened with irrelevant immigration UI.
- International users see authorization/sponsorship realism.
- English/French/Both remains the user's choice even when the engine recommends a language strategy.

## 10. Launch gate
V1 design is complete when a new user can complete this scenario end-to-end without conceptual gaps:
Profile → receive realistic opportunity → understand why → see blockers → choose pathway/job → get next actions → improve language/career readiness → understand funds/documents → track application → retain a post-arrival path.

Implementation may ship incrementally, but no new V1 feature category should be added unless it closes a gap in this scenario. Future Study, Founder, Family, Logistics and expanded Settlement functionality remains in the Master Product Inventory and must not delay the launch gate.

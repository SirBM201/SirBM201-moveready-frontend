# MoveReady V1 User Acceptance Journeys

These journeys are the design acceptance test. V1 must work for more than the founder's personal case.

## A — Local job seeker
User selects LOCAL, current country and target roles. Results prioritize realistic local vacancies. Immigration/sponsorship UI stays out of the way. User can tailor application material and track applications.

## B — International job seeker needing sponsorship
User selects INTERNATIONAL. A 95% skills match that explicitly refuses sponsorship is visibly not recommended. A lower skills match with confirmed employer support can rank higher on application viability. User understands the difference.

## C — Person already abroad seeking a better job
Current residence/work authorization is reused. Local vacancies in the residence country are treated as local opportunities; user can also enable international search without rebuilding their profile.

## D — Skilled migration without job offer
User starts from goal/profile rather than programme name. Opportunity Finder can surface legitimate non-employment PR/skilled pathways, show readiness gaps, funds/language/documents and next actions.

## E — English + French learner
User chooses Both and a 70/30 allocation. The platform may recommend another balance but does not override the choice. IELTS General and TEF Canada targets remain distinct; Practice/Mistakes Banks feed adaptive review.

## F — Family relocation
Family size/circumstances flow into pathway, proof-of-funds and document considerations where rules require them. The user can distinguish accompanying vs later family planning as the roadmap expands.

## G — Founder/entrepreneur
Opportunity Finder can preserve startup/entrepreneur/self-employment routes in the product inventory and compare them against employment/study routes without forcing V1 to build every founder workflow before launch.

## H — Post-relocation user
After a successful move, dashboard emphasis can transition toward settlement, renewals, local jobs, career growth and family settlement. The account remains useful rather than ending at visa approval.

## Acceptance rule
A feature is not considered well integrated merely because its page exists. It must receive relevant profile context, return an understandable result, expose trust/provenance where material, and hand the user to a concrete next action without unnecessary re-entry of data.
